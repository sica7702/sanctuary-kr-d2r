Sanctuary KR : D2R — 이미지 아이템 감정 시스템 설계안 v1

[목표]
스크린샷 업로드 → 옵션 자동 인식 → 사용자 보정 → 기존 감정 DB 교차검증 → WHY 감정 결과 출력.
단순 OCR이 아니라 '읽기 + 검증 + 설명'이 핵심이다.

[1단계: 프론트엔드]
- 이미지 업로드/드래그앤드롭
- 업로드 미리보기
- 자동 인식 진행 상태
- 인식된 아이템명/희귀도/부위/옵션/수치 편집
- 옵션별 인식 신뢰도 표시
- 감정 결과: 등급, 강점, 사용 빌드, 아쉬운 점, 최대치 대비 수치

[2단계: 이미지 인식 API]
- Vision/OCR API에서 아이템 툴팁 텍스트 추출
- 줄 단위 옵션 분리
- 한글 D2R 옵션명 표준화 사전 적용
- 숫자 오인식(3/8, 5/6 등) 보정 규칙
- 스킨/해상도 차이를 고려해 OCR 결과를 확정값으로 쓰지 않고 사용자 확인 단계 필수

[3단계: 감정 엔진]
- appraisal-data.js 기반 부위/접사 규칙 연결
- magic-data.js, rare-data.js와 조합 검증
- 일반 레어 vs 크래프트 고정옵 분리
- 최대치/접사 슬롯/생성 가능 여부 검증
- 직업/빌드 수요 가중치
- PvM/PvP, 래더/스탠 컨텍스트
- 가격 자동 확정은 제외

[4단계: WHY 엔진]
결과를 반드시 다음 4축으로 설명:
1) 왜 가치가 있는가
2) 어떤 빌드에서 쓰는가
3) 어떤 옵션이 핵심인가
4) 무엇이 붙었으면 한 단계 위인가

[권장 서버 구조]
Netlify Frontend
  → Serverless API (Netlify Functions / Cloudflare Workers / Supabase Edge Function 중 1)
  → Vision/OCR Provider
  → Normalizer
  → Sanctuary Appraisal Engine
  → JSON Result
  → Frontend Result UI

[개발 순서]
A. 현재 시안 UI 확정
B. 수동 입력 데이터를 기존 감정 DB에 실제 연결
C. 이미지 OCR API 연결
D. OCR 정규화 사전 구축
E. WHY 엔진 규칙화
F. 실사용 스크린샷 100~300장으로 오류 패턴 QA
G. BETA 공개

[현재 v33 시안의 범위]
- image-appraisal.html 신규 추가
- 실제 파일 업로드 미리보기 동작
- 샘플 OCR 스캔 애니메이션 동작
- 인식 결과 수동 수정 가능
- 데모 감정 결과/WHY UI 동작
- 실제 OCR/API 및 기존 감정 DB 계산 연결은 아직 하지 않음
